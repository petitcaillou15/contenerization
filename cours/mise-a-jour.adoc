== Mettre à jour une application

=== Changer de version

Une mise à jour = *changer l'image* (ou la configuration du Pod) dans le Deployment.

[source,bash]
----
kubectl set image deployment/web web=web:2.0
# ou : modifier le manifeste, puis
kubectl apply -f deployment.yaml
----

Kubernetes ne remplace pas tout d'un coup : il fait un *rolling update*.

=== Le rolling update

image::rolling-update.png[]

* Les Pods sont remplacés *progressivement*
* Un nouveau Pod doit être *prêt* (readiness) avant d'en supprimer un ancien
* Le service reste *disponible* pendant la mise à jour

=== Régler la stratégie

[source,yaml]
----
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
----

* `maxSurge` : combien de Pods *en plus* pendant la mise à jour
* `maxUnavailable` : combien de Pods *indisponibles* au maximum

=== Suivre un rollout

[source,bash]
----
kubectl rollout status deployment/web
kubectl get rs                       # l'ancien et le nouveau ReplicaSet
kubectl get pods -w
----

=== Historique et rollback

[source,bash]
----
kubectl rollout history deployment/web
kubectl rollout undo deployment/web
kubectl rollout undo deployment/web --to-revision=2
----

* Chaque version correspond à un *ReplicaSet* conservé
* Le *rollback* réactive l'ancien ReplicaSet
* Sans *readiness*, un rollout défaillant peut *casser tout le service* !
