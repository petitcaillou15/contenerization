== Le projet

=== L'application

Un *mini réseau social* : utilisateurs, posts, commentaires, notifications.

*Vous ne développez pas l'application* : vous recevez un code *qui fonctionne déjà*.

Pour le vérifier, un simple `docker compose` suffit :

[source,bash]
----
cp .env.example .env
docker compose up --build
----

Frontend sur `http://localhost:8080`, API sur `http://localhost:8081`.

*Votre travail* : conteneurisation, déploiement Kubernetes, communication, configuration.

=== Cahier des charges (1/2)

. *Images Docker* : multi-stage, `.dockerignore`, légères, reproductibles
. *Déploiement K8s* : Deployments (pas de Pods à la main), *Namespace dédié*, auto-réparation
. *Communication* : pas d'IP de Pods, découverte de services, accessible depuis l'extérieur

=== Cahier des charges (2/2)

[start=4]
. *Configuration* : aucune reconstruction d'image pour changer de config, configuration vs. secrets, *aucun secret dans une image*
. *Disponibilité* : health checks (probes), au moins un composant avec plusieurs replicas
. *Données* : la base de données reste *hors de Kubernetes* ; ses données doivent être *persistées*
. *Observabilité* : être capable de *montrer les logs* et *au moins une métrique* (ELK, Prometheus... : facultatif)

== Votre repo GitLab

=== À faire maintenant (15 min)

. Constituez vos groupes (*2 ou 3* étudiants)
. *Un* membre crée le projet sur le GitLab de l'école
. Ajoutez *vos camarades* (Maintainer) et *@chomton.emile* (pour suivi et notation)
. *Clonez* le dépôt du cours
. Premier commit (remplir le tableau des membres du `README.md`) + push

5 ou 6 groupes maximum !

=== Ajouter votre `origin`

Après le clone, `origin` pointe vers le *dépôt du cours*. À la place :

[source,bash]
----
git remote rename origin upstream   # le dépôt du cours : pour récupérer les nouvelles versions
git remote add origin <url-de-VOTRE-depot>
git push -u origin main
----

* *`origin`* = votre dépôt de groupe : pour le rendu
* *`upstream`* = le dépôt du cours : pour le cours et les futures versions
* `main` = branche principale du dépôt de groupe, qui sera évaluée

== À vous de jouer !

=== Objectif de la séance

Obtenir des *images propres*, une *base de données externe* qui fonctionne et persiste, et un *premier déploiement fonctionnel* de plusieurs composants.

*Initialiser votre repo.*

=== Ce qu'il y a à faire en séance 1

. Créer votre *repo GitLab* et y pousser le code (branche `main`)
. Améliorer les Dockerfiles (multi-stage, `.dockerignore`)
. Construire les images
. *Sortir PostgreSQL* dans un `docker-compose` séparé, le faire fonctionner, et vérifier que les *données sont persistées* (supprimez et recréez le conteneur : sont-elles toujours là ?)
. Créer un *Namespace*
. Écrire les premiers *Deployments*
. Déployer les premiers composants
. Supprimer un Pod : il revient tout seul ?
. Passer à plusieurs *replicas*
. Découvrir les *Services* : premières communications entre composants

=== Bonnes pratiques

* Un dossier `k8s/` avec un fichier par composant
* *Commitez régulièrement*
* Notez vos commandes : elles serviront au README
* Pas de secret dans les images ni dans le dépôt en clair
* En cas d'erreur : `kubectl describe` et `kubectl logs`

=== Aide-mémoire

[source,bash]
----
minikube image build -t users:1.0 ./services/users
minikube image ls
kubectl get all -n mini-reseau
kubectl apply -f k8s/
kubectl rollout status deployment/users -n mini-reseau
kubectl delete -f k8s/
----
